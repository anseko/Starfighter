# AGENTS.md

## Project overview

Unity multiplayer space game ("StarFighter") using **MLAPI** (`com.unity.multiplayer.mlapi` 0.1.0) — not Mirror. Mirror `.csproj` files in the repo root are Unity-generated artifacts; all game code uses `MLAPI` namespaces. URP render pipeline, .NET 4.7.1 target.

Dedicated server architecture: `ServerScene` runs headless; clients connect and get a role-based UI.

## Code layout

All game code lives under `Assets/Scripts/` in four namespace roots:

- **`Core`** — shared constants, enums (`UserType`, `UnitState`, `ZoneType`, `SpaceFieldType`), event types, input manager, data models, and import/export logic
- **`Net`** — server-side logic: `MainServerLoop` (entry point), `ServerInitializeHelper` (world init/save), `ConnectionHelper` (client RPC dispatch), and networked components in `Net/Components/`
- **`Client`** — client-side: camera, UI per role (`Client/UI/`), player/unit scripts (`Client/Core/`), and visual utilities
- **`ScriptableObjects`** — config asset classes: `SpaceShipConfig`, `SpaceUnitConfig`, `DangerZoneConfig`, `KeyConfig`, `ClientAccountObject`

Other directories:
- `Assets/Resources/Prefabs/` and `Assets/Resources/ScriptableObjects/` — runtime-loaded via `Resources.Load`
- `Assets/External assets/` and `Assets/Prefabs/` — art, models, particles (not code)

## Scenes

- **`ServerScene`** — dedicated server; starts `MainServerLoop` → `ServerInitializeHelper.InitServer()`
- **`MainMenu`** — client entry; login UI, then role-assigned UI via `ConnectionHelper.SelectSceneClientRpc`
- **`ObjectsBurials`** — supplementary scene

## Key patterns

### Role system
`UserType` enum (`Core/Enums.cs`) defines roles in ascending privilege order:
`Navigator < Spectator < SpaceStation < Pilot < Mechanic < Admin`

The server assigns roles in `MainServerLoop.OnConnectCallback`; the client switches UI in `ClientInitManager.Init{Role}()`. Roles above `Pilot` get ship ownership transfer.

### Singleton event buses
`CoreEventStorage`, `ClientEventStorage`, `NetEventStorage` — lazy singletons via `GetInstance()`, dispatch through `UnityEvent` subclasses. Do not create duplicates.

### Server world persistence
Ships, units, and danger zones are serialized to **JSON `.dat` files at the project root**:
- `ships.dat` — ship configurations
- `units.dat` — non-ship unit configurations
- `dangerZones.dat` — danger zone configurations
- `asteroids.dat` — name of the space field prefab to load

`ServerInitializeHelper` reads these on startup and writes them on quit (`SaveServer()`). If `.dat` files are missing, fallback loads ScriptableObjects from `Resources/ScriptableObjects/`.

### Object naming convention
GameObjects are named `{prefabName}|{id}` (separator: `Constants.Separator = '|'`). The codebase uses `GameObject.Find()` with this pattern — **changing object names will break lookups**.

### Network state
`NetworkSpaceUnitDto` wraps every game property in `NetworkVariable<T>` with custom write permissions (owner, server, admin, or mechanic can write). `SpaceUnitDto` is the serializable DTO used for persistence and network serialization.

### State machine
`UnitStateMachine` (`Client/Core/UnitStateMachine.cs`) implements three states for player ships: `InFlight`, `IsDocked`, `IsDead`. State transitions trigger docking, grapple release, beacon activation, and ownership transfer.

### Authentication
`MainServerLoop.ApprovalCheck` compares `GetHashCode()` of the `login+password` string — accounts are defined as `ClientAccountObject` ScriptableObjects.

## Gotchas

- **No build scripts, CI, or tests** — building and testing happens entirely in Unity Editor
- `.gitignore` excludes `*.csproj` and `*.sln` — these are auto-generated by Unity; do not hand-edit or rely on them
- `FindObjectOfType` / `FindObjectsOfType` is used extensively for runtime wiring — avoid creating duplicate instances of singleton-like MonoBehaviours
- `PlayerScript.localUsage` flag starts a host in `UNITY_EDITOR` only — this is the dev testing shortcut
- `DiscordApp.cs` is a stub with an empty auth token — do not add real credentials
- Some code comments are in **Russian**
- `asteroids.json` (note: `.json` not `.dat`) is an alternate export path used by `Importer.ExportAsteroids`
